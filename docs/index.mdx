Moltworld is an HTTP chat API where each eligible request is quoted and paid individually in WIF on Robinhood Chain. A user-controlled wallet authorizes each payment through x402, and successful responses include a signed receipt.

## The live payment loop

<Steps>
  <Step title="Discover a chat model">
    Read `GET /v1/models` or use the remote MCP server to find enabled chat models.
  </Step>
  <Step title="Quote the exact request">
    Submit the chat body to `POST /v1/quote`. The quote is free and is tied to that request shape.
  </Step>
  <Step title="Authorize one WIF payment">
    The chat endpoint returns an x402 `402 Payment Required` challenge with Robinhood Chain (`eip155:4663`), the WIF token, recipient, and exact amount. The user reviews and authorizes each call in their wallet.
  </Step>
  <Step title="Receive an answer and receipt">
    The gateway settles a valid payment, calls the selected model, and returns the AI response with a signed receipt that records the request and settlement.
  </Step>
</Steps>

A user-authorized mainnet WIF payment has been verified end-to-end with an AI response and settlement receipt. The remote MCP server remains keyless: it can relay a caller-signed payment, but it cannot approve, sign, or pay for the caller.

## Why return

An agent or application can repeat the same useful cycle: discover a model, quote the exact job, ask the user's wallet to authorize that call, then verify the answer's receipt. This gives software a per-call payment and proof-of-settlement flow without giving an agent the owner's wallet key. Repeated use is possible; public retention or repeat-user metrics are not currently published, so this should not be read as proof of a measured network effect.

## Current WIF support

WIF payments, owner-funded agent mandates and enabled marketplace APIs are available on Robinhood Chain. Marketplace listings require review; creator payouts use merchant-authorized transfers and on-chain reconciliation. Media and automatic WIF refunds remain unavailable. The remote MCP is keyless; local stdio MCP keeps its session key on the agent machine. See [Spending mandates](/products/mandates) and [Marketplace](/products/marketplace).
